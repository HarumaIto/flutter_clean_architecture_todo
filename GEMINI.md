## Project Context

You are an expert Flutter Engineer building a sophisticated **Todo / Task Management Application**. The project adheres to a strict **Layered Architecture** (Domain, Application, Infrastructure, UI) to ensure maintainability, scalability, and testability. The app prioritizes an **Offline-First** experience using local database persistence.

## Architectural Guidelines

### Core Architecture Patterns

  - **Architecture Style**: Layered Architecture.
      - **Domain**: Pure business logic (Task Entities, Value Objects, Repository Interfaces).
      - **Application**: Orchestration logic (Task UseCases, Reminder Services).
      - **Infrastructure**: External implementations (Drift Database, Firestore Sync, Local Notifications).
      - **UI**: Presentation layer (Task List, Task Detail, Add Task Sheet).
  - **State Management**: Riverpod with code generation (`@riverpod`).
  - **Data Layer**: Repository pattern.
      - **Source of Truth**: Local Database (Drift/SQLite) is the primary source of truth for UI.
  - **Immutability**: All data models use `Freezed` + `json_annotation`.

### Implementation Rules

#### 1\. State Management (Riverpod)

  - Use `@riverpod` annotation.
  - **UI Notifiers**: `ui/notifier/` should handle view states (loading, error, empty list).
  - **Providers**: Use `StreamProvider` for observing lists of tasks from the local database to ensure reactive UI updates.

#### 2\. Data Models & Mapping

  - **Domain Entities**: Use `Freezed`. Define rich behavior here (e.g., `task.isOverdue()`).
  - **Infrastructure Models**: Generated by Drift or defined for Firestore.
  - **Mapping**: Strictly convert Infrastructure Models to Domain Entities in the Repository layer. The UI never sees a Drift row object directly.

#### 3\. Offline-First Strategy

  - **Reads**: Always read from the Local Database (Infrastructure).
  - **Writes**: Write to Local Database first. If cloud sync is enabled, sync to Firestore in the background.

#### 4\. Features & Integration

  - **Local DB**: Use `drift` (preferred) or `sqflite` for structured data storage.
  - **Notifications**: Use `flutter_local_notifications` for task reminders.
  - **Filtering/Sorting**: Implement filtering logic (by date, priority) within the `infrastructure` (SQL queries) or `application` layer, not in the UI.
